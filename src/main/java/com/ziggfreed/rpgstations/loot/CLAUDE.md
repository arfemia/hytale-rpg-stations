# loot/

The loot model, its evaluator and the `Lootable`/`RollPool` stores are ziggfreed-common's (`com.ziggfreed.common.loot`); read its router, `zc-loot/src/main/java/com/ziggfreed/common/loot/CLAUDE.md` in ziggfreed-common, first. This package is only the station pass (`StationLootEngine`, whose javadoc holds its sinks, subject and roll order) and the one home of the station's grant-reporting rules.

- `Target:{Lootable}` extension rolls and `Target:{RollPool}` entries join zc's ONE table and pool composition as sources `ExtensionCatalog` registers at plugin setup, so every site that rolls an extended table sees them, station or not. Never merge rolls or pool entries at a call site or in a station-only resolve. The order is pinned (`ExtensionCatalogTest`), and a test that resolves an extended table registers the source in `@BeforeEach`.
- A roll that authors no `Trigger` reads `"Default"`, and a station pass asks only `"Cycle"` or `"Completion"`, so it never fires at a station; pools draw on the cycle pass. Say so in docs and javadoc, and `StationValidator` warns on it (`LOOT_TRIGGER_NEVER_ASKED`); never change the runtime here. A `Target:{Lootable}` extension's own rolls are exempt, since they join the table at every site that rolls it.
- The three station reward kinds register ONCE into `RewardKinds.shared()` at plugin setup (`StationRewardKinds.registerInto`), never a registry per pass. A test that drives a pass or validates with them calls `registerInto` in `@BeforeEach`: the registry is process-wide and `RewardKinds.clear()` empties it.
- `rpgstations:output_items` is a fractional tally summed over the cycle and resolved once by `OutputItemResolver`; everything downstream reports the landed count (`OutputItemResolver.reportable`), never the rolled one.
- Every grant path counts what it landed on the HUD itself (`StationService.notifyItemGain`), never on the notification feed: the Produce phase reports only the recipe's deterministic `Yield`, so an uncounted bonus reads in game as not working.
- A `Commands` payout is invisible to every listener and never counts as `STATION_OUTPUT`; author a payout that must be counted as `Items`.
- Never roll a drop list through `ItemModule` directly: the pass hands drop lists to zc's `GroundSpillSinks`, and `StationValidator`'s drop-list probe rolls through `NativeLootService.tryRollNative`.
